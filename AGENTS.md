## Notes

- Build: `npm ci`, then `npm run build-and-publish` (esbuild bundles `src/` to `dist/`, copies it to `docs/`; `docs/` is what gets served, so commit it). Node is not installed on the dev PC: a portable copy lives in `C:\Repos\Sloperator\publish\SloperatorData\tools\node-v24.22.3-win-x64` (put it on PATH for the session). `npx tsc --noEmit -p .` type-checks.
- Default sheet links are the production sheets from `HoC-Web-Server/RemoteSheetsList/remote_configs_sheets.csv` (public, CSV export works). `ChestPvp`, `EquipmentForgeConfig` and `EquipmentUpgradeConfig` are not in `remote_configs_sheets.csv` yet; their links were supplied by the user and are set in `src/configTables.ts`. An empty URL skips a table (PvP chests then fall back to `ChestSlot`). Forge keys are `Class_Type_Rarity`.
- The model follows the game client (Heroes-of-the-Chests), not the old v2 doc: only X3 slot spins pay out (`InitialChance` row of `SlotMachineBaseDrops`); chests = rarity from `ChestRarityRoll` (per source) + one variant per slot of `ChestSlot`/`ChestPvp`; gold from slots/chests/PvP/daily rewards is multiplied by the league `GoldIncomeMultiplier` (`ResourceRewardFactory`), PvP hero exp by `ExpIncomeMultiplier` (`UnitsExperienceHandler`), castle production and mini-events are not multiplied; season reset = `min(rating, ResetRating)` + `ResetRewardAmethysts` (`SeasonsLeaderboardService`).
- Offline check: bundle a small script with esbuild (`--platform=node`) that reads the CSVs exported from the production sheets and calls `parseGameConfig` + `runSimulation`; the browser page and the script gave identical numbers.
- Not simulated (no data/rules available): `HeroOverflowCap` overflow to amethysts, event hero-gacha sheets (`EventHeroGacha01*`, not on the server list), where forge shards come from, achievements.
